# OrbitFabric EDS-cFS Adapter 0.1.0

`v0.1.0` is the first public release of the OrbitFabric EDS-cFS Adapter.

It provides a deliberately narrow, evidence-backed interoperability path:

```text
OrbitFabric Core Integration Input Set
    -> EDS-cFS Projection Profile
    -> OrbitFabric EDS-cFS Adapter
    -> CCSDS EDS
    -> NASA EdsLib
    -> NASA cFS native EDS-enabled build/runtime
```

The retained acceptance chain proves:

- deterministic Core Integration Input Set consumption;
- explicit EDS-cFS Projection Profile validation;
- deterministic CCSDS EDS XML generation;
- machine-readable traceability;
- Core-conformant Integration Result generation;
- deterministic failure semantics and rollback;
- exact native EdsLib processing on the pinned lane;
- complete pinned `native_eds` build/install participation;
- generated command and telemetry API consumption by a fixed cFS application;
- runtime command dispatch and telemetry encode/decode;
- typed command argument delivery;
- mission-owned symbolic cFS target-allocation binding;
- negative/conformance runtime characterization;
- installed Adapter Manager execution after checkout source and acquisition material are removed;
- Project Lock lifecycle proof before publication;
- publisher release-byte verification before a GitHub Release is made public.

## Target allocation ownership

The public Profile binds OrbitFabric interfaces to mission-owned symbolic `CFE_MISSION` allocation identities. It does not encode SampleMission TopicId ranges as universal cFS policy.

The retained reference lane resolves:

```text
OF_DEMO_CMD_TOPICID        -> 160
OF_DEMO_STATUS_TLM_TOPICID -> 416
```

Those values are reference-mission evidence only. The selected cFS mission and MissionLib realization remain the final target-allocation authority.

## Runtime characterizations

Two results are intentionally documented rather than hidden behind adapter-generated guards.

### EDS ValidRange

The adapter projects the OrbitFabric `PeriodMs` range `100..60000` into EDS. On the validated native lane, out-of-range values can still reach the typed application handler. The release therefore does not claim automatic runtime enforcement of every projected EDS range.

### Undefined Function Code

A structurally valid OF_DEMO command carrying undefined Function Code `127` can reach the valid generated `payload.enable` handler on the frozen native lane. The release therefore does not claim automatic rejection of every unknown Function Code.

No adapter-local runtime validation or Function Code guard is inserted solely to make either property appear stronger than the validated target behavior.
